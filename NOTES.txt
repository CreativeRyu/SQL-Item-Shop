SQL Item Shop - Design Notes

Core idea
- SQL is not only the lesson goal. SQL is the tool the player uses to run and improve the shop.
- Money should reward learning progress and unlock useful tools, shop systems, and atmosphere.
- Essential SQL concepts should come from learning progress, not from paid unlocks.

Current next feature direction
- Next focus is content and progression:
  - Large Notebook paper sound polish.
  - Level 3 WHERE Advanced test / polish pass.
  - Large Notebook View polish / content expansion.
  - Sound effects later.

Money / shop item ideas
- SQL Notebook: existing core learning item.
- Large Notebook View: expanded reference view with syntax examples, schemas, known commands, and progress.
- Query History: stores recent queries and lets the player put them back into the editor.
- Query Blueprints: purchasable help per mission. Shows a full or partial example query, but the player still types it manually.
- Radio: unlocks music and sound controls.
- Error Analyzer: explains common SQL errors in plain language.
- Hint vouchers: optional paid help if the player is stuck.
- Schema Lupe is probably not needed as a separate item:
  - Players should discover schemas with PRAGMA table_info.
  - Discovered schemas should remain available in the Large Notebook View.

Shop progression ideas
- Buy more shelves or cabinets to offer more items.
- Expand the shop to allow more customers over time.
- Customers can buy items from inventory.
- Player uses SQL to inspect stock, sales, customers, and product data.
- Later, restocking can teach UPDATE and safe data changes.
- Reset / backup tools become relevant once destructive database operations are allowed.
- Shelf-slot gameplay:
  - Shelves have visible product slots.
  - Player can fill slots with products from inventory.
  - Customers buy from the visible shelf stock.
  - Shelf stock goes down when customers buy items.
  - Player has to restock shelves over time.
  - More or better shelves can be bought as shop upgrades.
  - This makes money useful for real shop growth, not only help items.
- Transactions fit naturally into restocking:
  - Restocking moves goods out of inventory and into shelf slots.
  - That changes two places and should be treated as one safe action.
  - Without a transaction, goods could leave inventory but never arrive on the shelf.
  - BEGIN / COMMIT / ROLLBACK can be taught as the safe way to move stock.
  - Shopkeeper framing: weight moved from one rack to another must not vanish halfway.

Crafting / recipe system ideas
- Customers may request crafted items, such as fruit salads or premium products.
- Recipes can be bought or unlocked.
- Crafting consumes items from inventory and creates a more valuable item.
- This can teach joins, aggregation, inventory checks, and later transactions.
- Possible tables: recipes, recipe_ingredients, products, inventory, sales, customers.

Pedagogical notes
- Keep required learning content unlocked by progress.
- Let money buy comfort, examples, orientation, atmosphere, and shop possibilities.
- Good players can spend extra money on cosmetics or shop upgrades.
- Struggling players can spend money on hints, blueprints, or schema tools.

Shopkeeper voice / Tonalitaet
- Der Shopkeeper ist der weise Mentor und Ausbilder des Spielers.
- Er macht keine Fehler und tritt mit ruhiger Autoritaet auf.
- Er trainiert fleissig im Gym, weil Koerper und Geist fuer ihn eine Einheit sind.
- Er ist Mentor, Ausbilder, Gym Bro und quasi der Beste, bleibt dabei aber immer respektvoll.
- Sein Humor darf trocken, selbstbewusst und leicht uebertrieben sein, aber nie gemein.
- Er motiviert den Spieler mit Disziplin, Klarheit und praktischen Ladenbeispielen.
- SQL-Erklaerungen sollen sich anfuehlen wie Training: sauberer Aufbau, klare Technik, keine Hektik.

Potential learning path
- SELECT basics
- Columns and FROM
- WHERE and comparison operators
- WHERE combinations: AND, OR, BETWEEN, LIKE
- ORDER BY and LIMIT
- Aggregates: COUNT, SUM, AVG
- GROUP BY
- HAVING
- JOIN basics
- Multiple JOINs
- Subqueries
- INSERT / UPDATE / DELETE in a safe shop-management layer
- Transactions for crafting/restocking safety

Moegliche kaufbare Items
- SQL Notebook: Basis-Notizbuch fuer gelernte Befehle, Tabellen und Fortschritt.
- Grosses SQL Notebook: erweiterte Ansicht mit Syntaxbeispielen, Erklaerungen, Schemas und typischen Fehlern.
- Query Blueprint: zeigt eine Musterquery oder eine teilweise ausgefuellte Loesung fuer eine Mission.
- Meister-Notiz: hochwertigere Hilfe mit kurzer Erklaerung, warum die Query funktioniert.
- Query History: speichert die letzten Queries und erlaubt, sie wieder in den Editor zu laden.
- Fehleranalyse: erklaert SQL-Fehler in normaler Sprache.
- Hinweis-Gutschein: kauft einen zusaetzlichen Tipp vom Shopkeeper.
- Rezeptbuch: schaltet Crafting-Rezepte fuer besondere Shop-Items frei.
- Crafting-Station: erlaubt das Kombinieren von Items zu wertvolleren Produkten.
- Lieferantenkontakt: erlaubt spaeter Restocking oder besondere Waren.
- Regal-Upgrade: mehr Platz fuer Produkte im Laden.
- Lager-Upgrade: mehr Bestand oder groessere Vorratsmengen.
- Kundentafel: zeigt Kundenwuensche, Verkaufsziele oder Tagesauftraege.
- Radio: schaltet Musik, Soundeffekte und Soundbuttons frei.
- Deko-Items: Poster, Lampen, Pflanzen oder Shopkeeper-Deko fuer Atmosphaere.
- Backup-Stein: spaeter Schutz oder Wiederherstellung, wenn gefaehrlichere SQL-Befehle erlaubt werden.
- Sandbox-Lizenz: erlaubt riskantere SQL-Operationen in einem sicheren Trainingsmodus.

- Grosses SQL Notebook MVP ist eingebaut:
  - Kleines Notebook bleibt Schnelluebersicht mit kurzen Beschreibungen.
  - Grosses Notebook oeffnet als erweiterte Lernansicht ueber den Expand-Button.
  - notebookContent.js enthaelt strukturierte Inhalte fuer Kategorien und Lern-Themen.
  - DQL, DML, DDL, DCL und TCL haben Registereintraege mit locked / known / completed Status.
  - DQL zeigt Erklaerungen, Syntax, Beispiele und Shopkeeper-Notizen fuer freigeschaltete Themen.
  - Noch nicht freigeschaltete Lerninhalte bleiben sichtbar, aber gedimmt.

    - SELECT
    - FROM
    - Wildcard *
    - WHERE
    - Vergleichsoperatoren
    - AND / OR / BETWEEN / LIKE
    - spaeter ORDER BY, LIMIT, JOIN usw.
  - Level-Metadaten markieren neue Notebook-Themen als abgeschlossen:
    - Level 0 markiert * zusammen mit FROM.
    - Level 2 markiert Vergleichsoperatoren.
    - Level 3 markiert AND, OR, BETWEEN und LIKE.
  - Tabellenansicht ist als Register gebaut:
    - Gruene Checkbox bedeutet: Tabellenschema ist freigeschaltet.
    - Seite 1 zeigt das Schema der ausgewaehlten Tabelle.
    - Seite 2 zeigt nach Schema-Unlock eine Vorschau mit SELECT * LIMIT 3.
    - Ohne Schema-Unlock wird keine Vorschau angezeigt.
  - PRAGMA table_info speichert echte Spalteninformationen dauerhaft im Notebook-State.
  - Alte / debuggeladene gruen markierte Tabellen koennen ihr Schema aus der aktuellen DB nachladen.
  - Grosses Notebook Layout wurde gepolisht:
    - zweispaltige Registerliste links.
    - Detailseite rechts.
    - deutsche Umlaute in sichtbaren Notebook-Texten bleiben sauber erhalten.
    - Abstaende, Registerbreiten und Checkbox-Platz wurden feinjustiert.

Naechster grosser Schritt
1. Level 3 testen und polishen.
   - Level 2 hat WHERE mit einzelnen Bedingungen abgeschlossen:
     - Textvergleich
     - Zahlenvergleich
     - Spaltenauswahl mit WHERE
     - einfache Vergleichsoperatoren
   - Level 3 baut WHERE als neues Hauptthema aus:
     - AND fuer mehrere Pflichtbedingungen.
     - OR fuer alternative Treffer.
     - BETWEEN fuer Wertebereiche.
     - LIKE fuer Textmuster.
   - Ziel:
     - Bedingungen bewusst kombinieren.
     - AND und OR klar voneinander unterscheiden.
     - BETWEEN als lesbare Bereichsform verstehen.
     - LIKE mit % als Platzhalter nutzen.
     - Noch kein ORDER BY in Level 3.
   - Naechster Schritt:
     - Level 3 komplett durchtesten.
