SQL Item Shop - Design Notes

Core idea
- SQL is not only the lesson goal. SQL is the tool the player uses to run and improve the shop.
- Money should reward learning progress and unlock useful tools, shop systems, and atmosphere.
- Essential SQL concepts should come from learning progress, not from paid unlocks.

Current next feature direction
- Mission feedback is now in-world:
  - Coin reward animation.
  - +Gold popup.
  - Complete stamp on the mission paper.
  - Level recap / next-level intro scroll.
- Next focus is content and progression:
  - Level 2 missions with WHERE.
  - Purchasable help items and help panel.
  - Large Notebook View.
  - Tablet/iPad landscape layout.
  - Radio, music, and sound effects.

Money / shop item ideas
- SQL Notebook: existing core learning item.
- Large Notebook View: expanded reference view with syntax examples, schemas, known commands, and progress.
- Query History: stores recent queries and lets the player put them back into the editor.
- Query Blueprints: purchasable help per mission. Shows a full or partial example query, but the player still types it manually.
- Radio: unlocks music and sound controls.
- Error Analyzer: explains common SQL errors in plain language.
- Hint vouchers: optional paid help if the player is stuck.
- Schema Lupe is probably not needed as a separate item:
  - Players should discover schemas with PRAGMA table_info.
  - Discovered schemas should remain available in the Large Notebook View.

Shop progression ideas
- Buy more shelves or cabinets to offer more items.
- Expand the shop to allow more customers over time.
- Customers can buy items from inventory.
- Player uses SQL to inspect stock, sales, customers, and product data.
- Later, restocking can teach UPDATE and safe data changes.
- Reset / backup tools become relevant once destructive database operations are allowed.

Crafting / recipe system ideas
- Customers may request crafted items, such as fruit salads or premium products.
- Recipes can be bought or unlocked.
- Crafting consumes items from inventory and creates a more valuable item.
- This can teach joins, aggregation, inventory checks, and later transactions.
- Possible tables: recipes, recipe_ingredients, products, inventory, sales, customers.

Pedagogical notes
- Keep required learning content unlocked by progress.
- Let money buy comfort, examples, orientation, atmosphere, and shop possibilities.
- Good players can spend extra money on cosmetics or shop upgrades.
- Struggling players can spend money on hints, blueprints, or schema tools.

Potential learning path
- SELECT basics
- Columns and FROM
- WHERE and comparison operators
- ORDER BY and LIMIT
- Aggregates: COUNT, SUM, AVG
- GROUP BY
- HAVING
- JOIN basics
- Multiple JOINs
- Subqueries
- INSERT / UPDATE / DELETE in a safe shop-management layer
- Transactions for crafting/restocking safety

Moegliche kaufbare Items
- SQL Notebook: Basis-Notizbuch fuer gelernte Befehle, Tabellen und Fortschritt.
- Grosses SQL Notebook: erweiterte Ansicht mit Syntaxbeispielen, Erklaerungen, Schemas und typischen Fehlern.
- Query Blueprint: zeigt eine Musterquery oder eine teilweise ausgefuellte Loesung fuer eine Mission.
- Meister-Notiz: hochwertigere Hilfe mit kurzer Erklaerung, warum die Query funktioniert.
- Query History: speichert die letzten Queries und erlaubt, sie wieder in den Editor zu laden.
- Fehleranalyse: erklaert SQL-Fehler in normaler Sprache.
- Hinweis-Gutschein: kauft einen zusaetzlichen Tipp vom Shopkeeper.
- Rezeptbuch: schaltet Crafting-Rezepte fuer besondere Shop-Items frei.
- Crafting-Station: erlaubt das Kombinieren von Items zu wertvolleren Produkten.
- Lieferantenkontakt: erlaubt spaeter Restocking oder besondere Waren.
- Regal-Upgrade: mehr Platz fuer Produkte im Laden.
- Lager-Upgrade: mehr Bestand oder groessere Vorratsmengen.
- Kundentafel: zeigt Kundenwuensche, Verkaufsziele oder Tagesauftraege.
- Radio: schaltet Musik, Soundeffekte und Soundbuttons frei.
- Deko-Items: Poster, Lampen, Pflanzen oder Shopkeeper-Deko fuer Atmosphaere.
- Backup-Stein: spaeter Schutz oder Wiederherstellung, wenn gefaehrlichere SQL-Befehle erlaubt werden.
- Sandbox-Lizenz: erlaubt riskantere SQL-Operationen in einem sicheren Trainingsmodus.

Roadmap / Naechste Schritte

Aktueller Stand
- Startscreen ist eingebaut.
- Ithaca ist die Hauptschrift fuer Titel/UI-Headlines.
- Shop-Buttons im Startscreen haben eigenen Holz/Metall-Look.
- Mission Complete Feedback ist eingebaut:
  - Geld zaehlt animiert hoch.
  - +Gold Popup erscheint neben der Geldanzeige.
  - Questzettel bekommt einen Complete-Stempel.
  - Naechste Mission wird erst nach dem Stempel geladen.
- Reset-Button ist aktuell bewusst komplett ausgeblendet.
- Shop-Visuals sind von der SQL-Datenbank getrennt:
  - products enthaelt keine sprite/pos_x/pos_y/scale Daten mehr.
  - Visuelle Daten liegen in shopLayouts/level0ShopLayout.js.
  - shop.js mapped DB-Daten auf Layout-Daten.
- Levelwechsel-Flow ist eingebaut:
  - Nach Levelabschluss erscheint ein Recap Screen.
  - Danach erscheint ein Next Level Intro Screen.
  - Level 0 -> Level 1 laeuft nicht mehr hart per Hint.
  - Weitere Level brauchen spaeter nur passende intro/recap Inhalte.

Naechster grosser Schritt
1. Level 2 didaktisch sauber ausarbeiten.
   - Level 1 festigt die in Level 0 gelernten Skills:
     - SELECT
     - FROM
     - einzelne Spalten
     - mehrere Spalten
     - verschiedene Tabellen
     - PRAGMA table_info
   - Level 2 fuehrt als neues Konzept WHERE ein.
   - Ziel:
     - einzelne Bedingungen verstehen.
     - Vergleichsoperatoren einfuehren.
     - SELECT-Spaltenauswahl mit WHERE kombinieren.
     - Noch keine komplexen AND/OR-Kombinationen erzwingen.
   - Moegliche Level-2-Aufgaben:
     - Produkt mit bestimmtem Namen finden.
     - Produkte unter / ueber einem Preis finden.
     - Kunden mit genug Geld finden.
     - Inventory-Eintraege mit wenig oder viel Bestand finden.
     - Passende Spalten anzeigen statt immer SELECT *.
   - Level 2 braucht:
     - eigene Missionenfolge.
     - Shopkeeper-Anlaesse / Mini-Story.
     - Recap-Daten am Levelende.
     - eventuell erweiterten Seed mit mehr Produkten, Kunden und Lagerdaten.

2. Help Panel und kaufbare Hilfe-Items bauen.
   - Neue Shop-Items:
     - hint.png als Shopkeeper-Hinweis.
     - blueprint.png als Query Blueprint / Loesungsgeruest.
   - Beide Items sollen als kaufbare Hilfen pro Mission funktionieren.
   - Wer die Hilfen nicht kauft, behaelt mehr Geld fuer andere Dinge.
   - Nach Kauf erscheinen kleine klickbare UI-Buttons im Help Panel unten rechts.
   - Help Panel:
     - zeigt gekaufte Hilfeelemente zur aktuellen Mission.
     - kann zwischen Hinweis und Blueprint wechseln.
     - bleibt getrennt vom Questpanel.
     - verdeckt keine wichtigen Quest- oder Editor-Elemente.
   - Hinweis:
     - kurzer Shopkeeper-Tipp.
     - gibt Richtung, aber keine komplette Loesung.
   - Blueprint:
     - zeigt Query-Geruest oder Lueckentext.
     - hilft beim Aufbau der Query, ohne sie komplett abzunehmen.
   - Diese Funktion ist wahrscheinlich kleiner als die grosse Notebook-Ansicht,
     weil sie erstmal nur missionsbezogene Inhalte anzeigen muss.

3. Story-Verteilung fuer Missionen konkretisieren.
   - Questpanel:
     - klare Aufgabe.
     - kurz, praktisch, waehrend der Mission nutzbar.
   - Shopkeeper-Dialog / Textbox:
     - witzige Einleitung.
     - kleiner Anlass fuer die Aufgabe.
     - Kommentare nach wichtigen oder schwierigen Missionen.
   - Tutorial:
     - nur fuer neue Konzepte oder neue UI-Werkzeuge.
     - Level 1 soll eher trainieren als dauernd unterbrechen.
   - Level Intro/Recap:
     - didaktische Einordnung.
     - was wurde gelernt / was kommt als Naechstes.
   - Wichtig:
     - Texte duerfen wichtige UI nicht verdecken.
     - Spaeter besonders wegen Tablet-Layout pruefen.

4. Grosses SQL Notebook planen und bauen.
   - Das kleine Notebook bleibt Schnelluebersicht im Hauptscreen.
   - Die grosse Notebook-Ansicht wird das eigentliche Lernwerkzeug.
   - Inhalte:
     - Syntax der gelernten Befehle.
     - kurze Erklaerungen.
     - Beispiele.
     - bekannte Tabellen.
     - gespeicherte Tabellenschemata.
     - eventuell typische Fehler.
   - Schema Lupe entfaellt wahrscheinlich als eigenes Item:
     - Der Spieler soll PRAGMA table_info einmal selbst ausfuehren.
     - Danach ist das Schema dauerhaft ueber das Notebook abrufbar.
     - SQL bleibt dadurch das Werkzeug, nicht ein Klick-Shortcut.

5. Tablet / iPad Anpassung planen.
   - Zielgeraet erstmal Tablet im Querformat.
   - Hochformat muss nicht priorisiert werden.
   - Aktuelles Desktop-Layout ist sehr breit:
     - Questpanel links.
     - Shop in der Mitte.
     - Output rechts.
     - Editor / Notebook unten.
   - Zu pruefen:
     - Passt die Drei-Spalten-Ansicht im Querformat noch?
     - Muss Output unter Shop oder neben Quest wandern?
     - Wie wird das Notebook auf Tablet platziert?
     - Verdecken Shopkeeper-Bubbles, Tutorial oder Popups wichtige UI?

6. Radio, Musik und Soundeffekte.
   - Radio als kaufbares Atmosphaere-Item.
   - Nach Kauf werden die vorbereiteten Audio-Buttons sichtbar.
   - Musik ins Spiel bringen.
   - Erste Soundeffekte einbauen:
     - Button-Klick.
     - Geld erhalten.
     - Mission Complete / Stempel.
     - Item gekauft.
     - Warnung / Fehler.

7. Weitere sinnvolle Geld-Sinks planen.
   - Geld soll mehr Bedeutung bekommen als nur Notebook kaufen.
   - Moegliche Items:
     - Radio.
     - Grosses Notebook.
     - Query History.
     - Query Blueprints / Meister-Notizen.
     - Deko / Atmosphaere.
     - Video- oder Cutscene-Sammlung.
   - Idee Video-Slot / Cutscene-Archiv:
     - Witzige Shopkeeper-Szenen koennen gesammelt werden.
     - Manche werden durch Events freigeschaltet.
     - Spieler koennen sie im Shop/Archiv kaufen oder dauerhaft sichern.
     - Letzte Szene erst nach Spielabschluss.

8. Cutscene-System planen.
   - Fuer besondere Momente:
     - Levelende
     - Item-Freischaltung
     - Notebook gekauft
     - Radio gekauft
     - erstes UPDATE
     - erstes DELETE
     - erstes DROP
     - Crafting freigeschaltet
   - Stil: kurze, witzige Shopkeeper-Szenen aehnlich Bancho-Vibes aus Dave the Diver.
   - Nicht jede Mission braucht Cutscene. Normale Missionen bekommen hoechstens kurzen Shopkeeper-Anlass.
   - Vermutlich eher spaeter bauen, wenn Levelinhalt, Notebook und Geld-Sinks klarer sind.

9. Source Material / Jupyter Aufgaben auswerten.
   - Notebook liegt in source_material/sql_aufgaben.ipynb.
   - Aufgaben nicht 1:1 uebernehmen.
   - Erst clustern:
     - SELECT
     - WHERE
     - ORDER BY / LIMIT
     - Aggregationen
     - GROUP BY
     - HAVING
     - JOIN
     - Mehrfach-JOINs
     - Subqueries
     - INSERT / UPDATE / DELETE
     - CREATE / ALTER / DROP
     - Transaktionen / Archivierung
   - Danach pro Level 5-8 Hauptmissionen plus optionale Bonusquests bauen.

10. Datenmodell v2 planen.
   - Aktuell sauberer als vorher, aber spaeter brauchen wir wahrscheinlich:
     - categories
     - suppliers
     - orders
     - order_items
     - recipes
     - recipe_ingredients
     - warehouses
     - warehouse_stock
   - Pro Level spaeter eigener Seed.
   - Pro Level spaeter eigenes ShopLayout.
   - Visuals bleiben ausserhalb der SQL-Lerndaten.
